Модель «сущность-связь»

E-Rモデル описывает предметную область: сущности (実体), их атрибуты (属性) и связи (関連). Тип связи — 1:1, 1:多 (один ко многим) или 多:多 (многие ко многим). Связь «многие ко многим» в реляционной базе разрешается через промежуточную таблицу.

Реляционная модель

Данные хранятся в таблицах (表, отношениях): строка — запись/кортеж (行, レコード), столбец — поле/атрибут (列, 属性).

КлючЯпонскийСмысл
Первичный主キーоднозначно определяет строку; не NULL и уникален
Кандидат候補キーлюбой минимальный набор, способный быть первичным
Внешний外部キーссылка на первичный ключ другой таблицы
Составной複合キーключ из нескольких столбцов

Ссылочная целостность (参照整合性): значение внешнего ключа должно существовать в связанной таблице. При удалении родительской записи возможны стратегии CASCADE, SET NULL, RESTRICT.

Реляционные операции

  • Выборка (選択, selection) — отобрать строки по условию;
  • Проекция (射影, projection) — отобрать столбцы;
  • Соединение (結合, join) — объединить таблицы по условию;
  • Объединение, пересечение, разность (和・積・差) — теоретико-множественные;
  • Декартово произведение (直積) — все пары строк.

Нормализация

正規化 устраняет избыточность и аномалии вставки, обновления и удаления.

ФормаТребование
1НФ (第1正規形)все значения атомарны, нет повторяющихся групп
2НФ (第2正規形)1НФ + нет частичной зависимости неключевых атрибутов от части составного ключа
3НФ (第3正規形)2НФ + нет транзитивной зависимости (неключевой атрибут зависит от другого неключевого)
НФБК (ボイス・コッド正規形)каждая детерминанта — потенциальный ключ
Как решать вопросы на нормализацию. Найдите составной ключ. Если какой-то атрибут зависит только от части ключа — нарушена 2НФ. Если атрибут зависит от неключевого атрибута — нарушена 3НФ.

Денормализация (非正規化) — осознанное нарушение нормальных форм ради скорости чтения; плата — риск рассогласования данных.

Индексы

インデックス ускоряет поиск ценой замедления вставки и дополнительного места. Типичная структура — B+ дерево (B+木): сбалансированное, все данные в листьях, листья связаны в список, что хорошо подходит для диапазонных запросов. Битовый индекс (ビットマップインデックス) эффективен для столбцов с малым числом различных значений.

Индекс бесполезен, если в условии столбец обёрнут функцией, или если выбирается большая доля таблицы — оптимизатор предпочтёт полное сканирование.

Архитектура СУБД

Трёхуровневая схема (3層スキーマ):

  • 外部スキーマ (внешняя) — представление данных для конкретного приложения;
  • 概念スキーマ (концептуальная) — логическая структура всей базы;
  • 内部スキーマ (внутренняя) — физическое хранение.

Такое разделение даёт независимость данных (データ独立性): изменение хранения не ломает приложения.

Распределённые и нереляционные базы

  • 分散データベース — данные на нескольких узлах; требуется двухфазная фиксация (2相コミット) для согласованности транзакций;
  • レプリケーション — копии данных для отказоустойчивости и чтения;
  • NoSQL — хранилища «ключ-значение», документные, колоночные, графовые; жертвуют строгой согласованностью ради масштабирования;
  • データウェアハウス — хранилище для анализа; данные собираются процессом ETL, анализируются через OLAP (многомерный куб, срезы и детализация — ドリルダウン), тогда как повседневная работа — это OLTP;
  • データマイニング — поиск закономерностей в больших массивах данных.
